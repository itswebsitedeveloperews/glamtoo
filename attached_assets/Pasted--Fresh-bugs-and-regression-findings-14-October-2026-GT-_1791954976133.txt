# Fresh bugs and regression findings — 14 October 2026

## GT-010 — High — Newly created product cannot enter checkout

- Route: /product/qa-launch-20261014-1791952755723 → /cart → /checkout.
- Steps: Create/publish a simple product with a unique ID (this fixture used £1, stock2, Handbags and an existing image). Add it in a fresh guest context. Open its nonempty basket. Click Go to checkout.
- Expected: Checkout retains the line and offers billing/payment.
- Actual: Navigation reaches /checkout then /cart about40ms later. Nonempty basket still shows the item. Reproduced by direct checkout navigation and by basket link; no order created for this fixture.
- Evidence: [navigation record](evidence/new-product-checkout.json), [screenshot](evidence/new-product-checkout-redirect.png), [trace](evidence/new-product-checkout-trace.zip), [source condition](evidence/launch-facts.json).
- Cause: Public compiled checkout code redirects when its resolved item array has length0. Failure to await catalogue hydration before that redirect is inferred from the new-ID-only failure and navigation trace; backend/source repository was not inspected.
- Fix: Distinguish catalogue loading from a truly empty/invalid basket. Await authoritative catalogue/inventory before resolving lines or redirecting. Cover newly created products, reload/direct checkout and unavailable products in regression tests. Fixture deleted after reproduction.
