13 October 2026 · Public-site review + supplied source ZIP

Glam Too pre-launch review

Recommendation: hold launch until the high-priority findings are resolved and the remaining staging checks pass.

Reviewed glamtoo.webdesignessex.io and Glam-Too-Boutique.zip. This is a functional review, read-only HTTP audit and targeted source/security review. It is not a guarantee that every defect or vulnerability has been found. The ZIP was not proven byte-for-byte identical to the deployed version.

What passed

  • All 39 URLs in the current sitemap returned HTTP 200. A deliberately missing URL returned 404. HTTP redirected to HTTPS; HSTS was present.
  • Seven tested private API routes rejected anonymous access with 401.
  • All 15 published catalogue product pages were inspected. No broken currently loaded product images or mobile horizontal overflow were detected in these checks; not every gallery image was loaded.
  • Search, price sorting, pagination, product size selection, gallery navigation/enlargement, guest wishlist persistence, adding a product to the basket and shipping-total recalculation worked in the tested flows.
  • Desktop (1440px) and mobile (390px) layouts were sampled. Stripe card fields rendered. No console errors were captured in the sampled browser checks; this is not a site-wide console guarantee.
  • All 26 standalone tests passed: SEO HTTP/metadata, category slugs, product pricing and shared shipping calculations.
  • Full workspace TypeScript checks passed.

Findings

GT-01 · High · Backend · reproduced locally

Admin email allowlist does not require verification

adminAuth.ts:25–30 grants admin access when any email address matches ADMIN_EMAILS, regardless of its verification status. An isolated call with an unverified allowlisted address returned true. Live exploitability depends on Clerk account/email settings; no live privilege escalation was attempted.

Action: Require a verified address or, preferably, an explicit trusted user-ID/role assignment. Test unverified and secondary addresses.

Evidence: artifacts/api-server/src/adminAuth.ts:25. Source paths are relative to the extracted project.

GT-02 · High · Backend · source finding

Checkout can reserve inventory without payment or application-level throttling

The anonymous payment-intent route creates an order and reserves stock before card confirmation. Reservations last 30 minutes. No checkout rate limit, per-owner active-reservation cap, or request idempotency key was found in the application. Repeated abandoned requests can tie up stock. Hosting/WAF protections remain unverified.

Action: Add distributed throttling, bounded active reservations and idempotent retries. Validate this in an isolated database; do not load-test the live store.

Evidence: artifacts/api-server/src/routes/stripe.ts:556; 607; 684. Source paths are relative to the extracted project.

GT-03 · High · Frontend · source confirmed

Newsletter signup is not connected

The footer form uses action="/" and method="get". Submission only navigates to /?email=...; there is no subscription request or success/error handling in that form. The address also becomes part of the URL/history. No real email was submitted.

Action: Connect a real subscription endpoint/provider, use POST, and show a confirmed result. Remove the form until connected if necessary.

Evidence: artifacts/glam-me/src/App.tsx:1028. Source paths are relative to the extracted project.

GT-04 · High · Frontend · observed

Returns and delivery promises conflict

FAQ: returns within 28 days of delivery; standard £3.95, free from £75; express £6.95. Returns/product pages: 21 days from purchase. Product delivery and checkout: standard £3.99, free from £100; next day £5.99; Saturday £8.99. FAQ timing also differs.

Action: Choose the approved policy and populate FAQ, product, checkout and returns content from the same settings.

Evidence: /faq; /returns; /product/military-style-jacket; /checkout; App.tsx:2101–2102. Source paths are relative to the extracted project.

GT-05 · Medium · Frontend · observed

Promoted collections have no products

New In/New Arrivals, Purses, Jewellery and Trousers showed 0 pieces. New In remains empty after loading even though the full shop has 15 products and uses New in sorting. The category filter only matches explicit product categories/children; it does not implement a new-arrival collection.

Action: Populate collections or change/hide the links. Implement New In as an explicit curated or date-based collection.

Evidence: /category/new-in; /category/purses; /category/jewellery; /category/trousers; App.tsx:1431. Source paths are relative to the extracted project.

GT-06 · Medium · Frontend · observed and source confirmed

Seed products and incorrect prices appear during loading

Military Style Jacket initially showed £35.99 on product, basket and checkout, then changed to £29.99. Homepage initially showed Luna/Ella/Mila products before switching to the real catalogue. Final basket maths was correct: £29.99 + £3.99 = £33.98. getStorefrontProducts() falls back to bundled catalogue data before the shared catalogue is loaded.

Action: Render a loading state or bootstrap the authoritative catalogue. Never display seed/demo prices as a live quotation.

Evidence: artifacts/glam-me/src/App.tsx:493; /product/military-style-jacket; /cart; /checkout. Source paths are relative to the extracted project.

GT-07 · Medium · Backend · reproduced locally

Saved-payment customer lookup stops after 100 customers

findStripeCustomer calls customers.list({limit:100}) once and ignores has_more. A mock first page with has_more=true returned null without requesting another page. Older customers can lose access to saved cards and receive duplicate Stripe customer records.

Action: Persist Stripe customer IDs by account and use them directly. Migrate existing mappings or paginate safely.

Evidence: artifacts/api-server/src/routes/stripe.ts:281–296. Source paths are relative to the extracted project.

GT-08 · Medium · Backend · source and HTTP confirmed

Credentialed CORS reflects arbitrary origins

cors({credentials:true,origin:true}) reflects an Origin of https://example.com and returns Access-Control-Allow-Credentials:true. The inspected unauthenticated private endpoint still returned 401; this is not proof of cross-site data theft. Cookie and Clerk behaviour must be tested with a staging account.

Action: Use an explicit storefront/admin origin allowlist and verify CSRF protection across state-changing routes.

Evidence: artifacts/api-server/src/app.ts:56; /api/account/profile. Source paths are relative to the extracted project.

GT-09 · Medium · SEO · HTTP and DOM confirmed

Staging site is explicitly indexable

robots.txt allows public crawling, public pages use index,follow, and sitemap/canonical URLs point to glamtoo.webdesignessex.io. Appropriate production configuration depends on the final domain.

Action: If this is staging, prevent staging indexing. On the final domain set SEO_SITE_ORIGIN, rebuild the sitemap/canonicals and verify redirect behaviour.

Evidence: /robots.txt; /sitemap.xml; artifacts/api-server/src/seo.ts:19. Source paths are relative to the extracted project.

GT-10 · Medium · Dependencies · npm audit

Dependency advisories require triage

Full lockfile audit: 21 advisories (14 high, 6 moderate, 1 low). Production-only audit: 2 (braces high via http-proxy-middleware > micromatch; uuid moderate via Google Cloud dependencies). Advisory severity does not establish exploitability in this application. Development dependencies also include frontend tooling, so production-only filtering is not a complete browser-bundle analysis.

Action: Review affected call paths, upgrade compatible dependencies, rerun the audit and regression suite. Full machine-readable audit files accompany this report.

Evidence: dependency-audit.json; dependency-audit-production.json. Source paths are relative to the extracted project.

GT-11 · Medium · Catalogue · observed

Product information is incomplete

Seven of the 15 products had no Description accordion: Mini Tote Bag, Button Up Short Sleeve Blazer, Leather Cape Jacket, Button Up Belted Trouser Set, Denim Trim Ribbed Cardigan, Printed Aysemetric Tracksuit and Mesh Floral Sleeve Tracksuit. Several clothing items have no size selector and no explicit one-size fit explanation.

Action: Complete product descriptions, materials, care and product-specific sizing; confirm that products without variations are intentionally one-size.

Evidence: Product pages listed above. Source paths are relative to the extracted project.

GT-12 · Low · Frontend · observed and source confirmed

Navigation labels do not match their destinations

Sale links to the unfiltered shop. Style Journal links to About. Size Guide links to the FAQ rather than the actual product size table. Contact Delivery & returns redirects to a returns page with no delivery-rate table.

Action: Provide the promised pages/filters or rename the links so customers know what they will get.

Evidence: artifacts/glam-me/src/App.tsx:1009; 1025–1027; /contact. Source paths are relative to the extracted project.

GT-13 · Low · Accessibility · observed and source confirmed

Mobile menu does not close with Escape

At 390px, Escape on the open-menu control left aria-expanded=true. The source Escape handler only closes search, not the menu. The overlay also leaves background content in the accessibility tree.

Action: Implement keyboard dismissal, focus management and appropriate background inertness; test keyboard navigation through the complete menu.

Evidence: artifacts/glam-me/src/App.tsx:836–1009. Source paths are relative to the extracted project.

GT-14 · Low · Technical · observed

SEO and security-header improvements

No Product JSON-LD was found on checked product pages. Homepage has no og:image. HTTP responses had HSTS and HTML nosniff, but no CSP, frame protection or Referrer-Policy in the inspected headers. These omissions alone do not prove a vulnerability.

Action: Add accurate Product structured data and a homepage social image. Configure a tested CSP/frame policy that permits required Stripe and Clerk integrations.

Evidence: Homepage/product DOM; http-results.json. Source paths are relative to the extracted project.

GT-15 · Verify · Deployment · partly observed

Launch configuration and business content need sign-off

The public Stripe key is pk_test mode. Contact lists +44 20 7123 4567; ownership/accuracy has not been verified. Privacy and terms pages are very short and omit details such as retention and fuller business identification. Email delivery configuration, webhook destination, production domain and actual receipt delivery are not verified.

Action: Confirm the real domain, business details and approved policies. Verify Stripe live configuration and signed webhooks at launch, then test order/refund emails with approved recipients. Do not enable live payments during this audit.

Evidence: /api/stripe/payment-config; /contact; /privacy; /terms; stripeBootstrap.ts:12; emailRecipientPolicy.ts:4–6. Source paths are relative to the extracted project.

GT-16 · Verify · Build · observed

Production build could not be verified on this Windows machine

TypeScript checks pass, but the frontend production build fails because @rollup/rollup-win32-x64-msvc is absent. pnpm-workspace.yaml deliberately excludes Windows native build packages. This is a portability limitation, not proof that the Linux deployment build fails.

Action: Run the clean frozen-lockfile production build and backend tests in the intended Linux CI/deployment environment, or support Windows native packages.

Evidence: pnpm-workspace.yaml:98–147. Source paths are relative to the extracted project.

What remains unverified

  • Authenticated admin/customer flows, account verification/recovery emails and access isolation between real test accounts.
  • A complete sandbox purchase, 3-D Secure, declined card, abandoned payment, duplicate webhook, refund, stock contention and coupon lifecycle.
  • Database-backed backend regression tests. They require a dedicated PostgreSQL test database; no database credentials or service were available, and production was not used for tests.
  • Actual order/contact/refund email arrival, provider logs, deployment environment, backups, restore procedure and monitoring.
  • Load testing, comprehensive penetration testing, full WCAG compliance, Safari/Firefox/real-device coverage and measured Core Web Vitals.

What is needed to finish launch sign-off

  1. Confirm the final live domain and approved returns/delivery policy.
  2. Arrange staging admin and ordinary customer test accounts, a dedicated test database and read-only hosting/application logs through a secure access method. Do not paste passwords or keys into chat.
  3. Provide an approved test inbox and confirm permission to create sandbox orders/accounts and send clearly labelled test messages. Public Stripe configuration currently indicates test mode, but provider/admin access is still needed to verify the complete flow.
